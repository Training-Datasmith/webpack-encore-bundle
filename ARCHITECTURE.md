# Architecture: webpack-encore-bundle

## Purpose

A Symfony bundle that integrates Webpack Encore with Twig templates. Reads the `entrypoints.json` and `manifest.json` files generated by Encore and exposes Twig functions (`encore_entry_script_tags`, `encore_entry_link_tags`) that output the correct `<script>` and `<link>` tags with cache-busted URLs and optional subresource integrity hashes.

## Directory Structure

```
src/
  Webpack_Encore_Bundle.php               - Bundle class
  Asset/
    Entrypoint_Lookup.php                 - Reads entrypoints.json; resolves JS/CSS files for an entry
    Entrypoint_Lookup_Collection.php      - Manages multiple Encore builds (multi-build support)
    Entrypoint_Lookup_Collection_Interface.php
    Entrypoint_Lookup_Interface.php
    Integrity_Data_Provider_Interface.php - Contract for SRI hash providers
    Tag_Renderer.php                      - Renders <script> and <link> HTML tags
  Twig/
    Entry_Files_Twig_Extension.php        - Registers Twig functions/tags backed by Tag_Renderer
  DependencyInjection/
    Configuration.php                     - Bundle config schema (output_path, builds map, etc.)
    Webpack_Encore_Extension.php          - Loads service definitions and wires config values
  CacheWarmer/                            - Symfony cache warmer: pre-loads entrypoints.json on warm
  Event/                                  - Events dispatched during entrypoint resolution
  EventListener/                          - Listeners (e.g., reset lookup between requests in test env)
  Exception/                              - Domain exceptions (entry not found, etc.)
  Resources/                              - Service definition YAML files
```

## Key Design Decisions

- **JSON manifest driven**: Rather than generating asset URLs at request time, the bundle reads pre-built `entrypoints.json` output by Webpack Encore. This keeps the bundle stateless and fast.
- **Multi-build support**: `Entrypoint_Lookup_Collection` allows multiple named Encore builds (e.g., separate admin and front-end builds) configured under the `builds` key.
- **SRI support**: `Integrity_Data_Provider_Interface` allows plugging in subresource integrity hash providers for security-conscious deployments.
- **Twig function surface**: All rendering logic is isolated in `Tag_Renderer`; the Twig extension is a thin adapter, making the rendering logic testable without a Twig environment.

## Extension Points

- Implement `Integrity_Data_Provider_Interface` to supply SRI hashes from a custom source.
- Register additional Encore builds via the `webpack_encore.builds` configuration key.

## Dependency Flow

```
Twig: {{ encore_entry_script_tags('app') }}
  └─> Entry_Files_Twig_Extension
        └─> Entrypoint_Lookup_Collection — select active build
              └─> Entrypoint_Lookup — parse entrypoints.json, return JS/CSS file list
        └─> Tag_Renderer::render_script_tags() — emit <script src="..." integrity="..."> HTML
```
